# SolarPulse for Android

Native Android client for SolarPulse (solar-fleet monitoring). Kotlin 2.1 + Jetpack Compose
(Material 3), minSdk 26, target/compile SDK 36. It follows the shared contract in
[`../docs/PLATFORM.md`](../docs/PLATFORM.md): same data model, same deterministic simulator,
same ROI formulas and alert semantics as the web app (`../src`) and the iOS app (`../ios`).

## Requirements

- Android Studio Narwhal (2025.1) or newer — AGP 8.11
- JDK 17+ (the Gradle daemon runs fine on 17 or 21)
- Android SDK Platform 36 (Android Studio installs it on first sync)

The Gradle wrapper (Gradle 8.14.3) is checked in; no global Gradle needed.

## Project layout


## Build & run

```bash
cd android
./gradlew :app:assembleDebug          # APK in app/build/outputs/apk/debug/
./gradlew :app:installDebug           # on a connected device / emulator
```

Or open the `android/` folder in Android Studio and run the `app` configuration.

`settings.gradle.kts` only includes `:app` when an Android SDK is found (`sdk.dir` in
`local.properties`, which Android Studio writes, or `ANDROID_HOME` / `ANDROID_SDK_ROOT`).
On machines without an SDK (CI test jobs, containers) only `:core` is configured, and the
Android Gradle Plugin is not even downloaded — see the `buildscript` block in `build.gradle.kts`.
Pass `-Psolarpulse.skipApp=true` to force that mode.

## Supabase (optional)

Without credentials the app runs in **demo mode**: the seed data (16 sites, devices, tickets,
invoices, alert rules) is generated by the shared simulator and persisted as JSON in the app's
files directory (`files/solarpulse-db-v1.json`); any e-mail + password signs in.

To use a real backend:

1. Run [`../supabase/schema.sql`](../supabase/schema.sql) in the Supabase SQL editor.
2. Copy `local.properties.example` to `local.properties` (keep `sdk.dir`) and set
   ```properties
   SUPABASE_URL=https://<project-ref>.supabase.co
   SUPABASE_ANON_KEY=<anon key>
   ```
   (environment variables with the same names also work, e.g. in CI).
3. Rebuild. The values are compiled into `BuildConfig`; sign-in becomes Supabase e-mail/password.

With Supabase, alert rules are evaluated by the `evaluate-alerts` Edge Function; vendor
credentials are written only through `rpc('set_integration_secret')` and never read back;
sites with a `readings` row from the last 15 minutes show the real power with a **Live** badge.

## Tests

```bash
./gradlew :core:test
```

`:core` tests compare the Kotlin port against values produced by the web's TypeScript code with a
frozen clock (`core/src/test/resources/web-reference.json`): FNV-1a `hash`/`rand` bit-for-bit,
`siteKw`/`siteDayKwh` (e.g. site-01 on 2026-06-21 = 4545.852236393882 kWh, within 1e-6), the full
seed (sites, devices, tickets, invoices, notifications, alert rules), energy flow, simulated
weather, portfolio/site ROI (payback, ROI, NPV, IRR, LCOE) and the alert firings. They also cover
hand-computed ROI/IRR cases, alert semantics (6-hour cooldown, 14:00 yield check, scopes,
thresholds), formatting (Latin digits in every language, Uyghur dates) and JSON round-trips.

Regenerate the fixture after changing the web simulator:

```bash
TZ=Asia/Shanghai node --experimental-strip-types android/tools/gen-web-reference.mjs \
  src/lib android/core/src/test/resources/web-reference.json
```

## Localization

`res/values{,-ug,-ar,-tr}/strings.xml` are **generated** from the web dictionaries
(`src/i18n/*.ts`, the source of truth) plus a few Android-only strings in
`tools/i18n/extras.mjs` (authored in all four languages):

```bash
node --experimental-strip-types android/tools/i18n/convert.mjs .     # from the repo root
python3 android/tools/i18n/check-resources.py .                       # validates keys, placeholders, XML
```

The language is switched in-app (Settings or the login screen) with
`AppCompatDelegate.setApplicationLocales` (`res/xml/locales_config.xml` also exposes it in the
system's per-app language settings). Uyghur and Arabic mirror the layout (RTL); numbers always use
Latin digits (`-u-nu-latn` locale extension + en-US number formatting).

## Release / Play Store notes

- Set `versionCode` / `versionName` in `app/build.gradle.kts`; add a `signingConfig` for your
  upload key (or sign in CI). Release builds use R8 (`isMinifyEnabled`, `isShrinkResources`).
- Build an App Bundle: `./gradlew :app:bundleRelease`.
- Target SDK 36 meets the current Play requirement for new apps and updates.
- Permissions: `INTERNET`, `ACCESS_NETWORK_STATE`, `POST_NOTIFICATIONS` (requested at runtime on
  Android 13+ for alert-rule notifications). No location permission is used.
- Data safety form: e-mail (account), app activity/data you enter; data is sent only to your own
  Supabase project and to Open-Meteo (city coordinates for weather) and OpenStreetMap tile servers.
  Demo mode stores everything on the device. Backups are disabled (`allowBackup=false`).
- OpenStreetMap tiles: the app identifies itself with its package name as User-Agent, per the
  OSM tile usage policy; consider a commercial tile provider for heavy production use.
- Provide a privacy policy URL and screenshots for phone and tablet (the UI switches to a
  navigation rail on large screens).
